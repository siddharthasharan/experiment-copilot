# Chat — turn-by-turn, like SocialPulse

The showroom now has a full-screen chat, modelled on SocialPulse's
chat-only view: the scorecard is hidden while chatting, the input and
Send stay pinned at the bottom, and messages scroll above them.

## How to open it

- From the scorecard: click **Chat — ask about a scenario** in the header.
- From any case view: click **Chat about this scenario** — it opens the
  chat already reviewing that scenario.
- Back to the scorecard: **Show scorecard**. **New chat** restarts with
  the scenario list.

## The first message: which scenarios are available

A new chat opens with the full list, grouped by track — Baseline
metrics (7), Triggered analysis (3), Interaction effects (4) — plus
clickable chips for every scenario, so you never have to guess a name.
Example prompts are given: `Review the whale trap`,
`Should we launch clean_win?`, `What is SRM?`

## The turn flow

1. **Review.** Ask about a scenario and the chat shows its real
   scorecard numbers: verdict, metrics table, reviewer flags, n.
   Nothing here is recomputed or paraphrased from memory — it is the
   same data object the scorecard renders.
2. **Diagnosis.** Ask `Diagnosis` / `Why is it inconclusive?` and the
   chat shows what actually happened (the trap reveal) and why it
   matters, with the evidence behind it.
3. **Recommendation + next steps.** Ask `Recommendation and next
   steps` and the chat gives a launch call derived from the verdict
   (Ship it / Don't ship / Don't decide yet / Throw this run out)
   plus the concrete next steps for that trap — e.g. for the peeker's
   mirage, wait for the pre-committed horizon and pre-register looks;
   for whale variance, report the median and a winsorized sensitivity
   check alongside the mean.
4. **PM/Eng brief.** Ask `PM/Eng brief` for a short, copyable summary
   of the whole thread: verdict, headline evidence, recommendation,
   next step.

## Methodology questions (RAG)

Questions in the form `What is SRM?`, `How does CUPED work?` are
answered from `rag/corpus.json` (inlined into the page at build time
by `scripts/build_showroom.py`, so the page still works from
`file://` with no server and no API key). Retrieval is the same
dependency-free keyword scorer as `evals/retrieval.py` — keywords x3,
title x2, body x1 — mirrored in JavaScript. Each answer cites the
corpus note and its sources, and offers the related scenario as a
follow-up chip when one exists.

Questions that match neither a scenario nor a corpus note get a
clarification listing what *is* available. The chat never invents an
answer, a number, or a verdict.

## Determinism, and what the chat is not

- No LLM, no server, no API key, no network calls. The chat is
  vanilla JavaScript in `docs/index.html`, generated by
  `scripts/build_showroom.py` from the scorecard payload, the corpus,
  and the `CHAT_NEXT_STEPS` table in that script.
- Recommendations are deterministic rules over the verdict and the
  trap design. They are not forecasts, and they are not a substitute
  for re-running an experiment after a fix.
- The chat does not run new analyses: it cannot change n, lift, or
  traps. For that, regenerate data in Codespace (see README Quickstart).

## Tests

`tests/test_chat_showroom.js` drives the chat through scripted
conversations in Node, loading the script straight from the built
`docs/index.html`:

- initial message lists all 14 scenarios;
- whale: review (INCONCLUSIVE) -> diagnosis -> recommendation
  (median/winsorized) -> brief;
- peeker: review (INCONCLUSIVE) -> diagnosis -> recommendation
  (pre-register looks);
- clean win: review (LAUNCH) -> recommendation (Ship it);
- `What is SRM?` retrieves the Sample Ratio Mismatch note;
- an unmapped question clarifies instead of answering;
- `Another scenario` returns to the scenario list.

Run it with `node tests/test_chat_showroom.js`. All cases pass.
The retrieval evals (`evals/run_evals.py`, 25/25 top-3) still pass
unchanged — the corpus was not edited for the chat.
